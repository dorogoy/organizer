## Findings

Every finding carries its source. Sub-agent-produced findings were re-checked against primary sources before routing; two were corrected in the process (see F-A/agg notes).

### F1 — Late discarded rescue success re-arms a degraded deal's control (fix now)

- **Source:** `lib/ui/dispenser/dispenser_screen.dart:464-469` (success branch clears `_degradedRescueDealId`/`_autoRescueFiredForDeal` unconditionally) vs the guarded failure branch at `:485-490`; `lib/dispenser/dispenser_controller.dart:673-674` (a delivered-then-discarded landing returns `DispenserRescueSucceeded`).
- **Evidence:** the uncommitted retro repro fails at HEAD: two parked flights (ask A → skip mid-flight → ask B → B fails → A delivers late). A's discarded success lands quietly (facts empty, successor stands — correct), but then taps B's secondary a third time: `slicer.calls` = 3, expected 2 — B's control re-ASKS after its cause was already stated, breaking FR-5's "skip-only for the rest of that deal".
- **Root cause:** the screen cannot distinguish delivered-and-landed from delivered-and-discarded; the success branch clears the markers of whatever deal currently stands, without the `dealStands` check the failure branch carries.
- **Verification gap (bmad-review, confirmed):** the committed suites pin one-flight late arrivals (`dispenser_screen_test.dart:2381, :2447`) but never a second ask after a degrade plus an out-of-order success — the only coverage is the untracked repro.
- **Related, lower confidence:** the markers are keyed by item id, not deal identity (`:579-588`) — a same-item re-deal inside one State lifetime would inherit markers. The committed per-deal test (`the degrade is per-deal: a session close ends it`) pins the close path; the gap is theoretical but the fix (keying by deal identity) falls out of the same guard.

### F2 — The auto-rescue heuristic never fires for deals minted by non-answer write paths (fix now)

- **Source:** `lib/ui/dispenser/dispenser_screen.dart:599,637` (`_commitView` owns the auto-fire) vs nine direct commit sites `:792, :807, :847, :894, :909, :950, :1124, :1171, :1222` (pocket declare, energy answer, report, pause, extend, both dismissals) that call `_endRescueMarkersIfDealEnded(view); setState(...)` without the heuristic.
- **Consequence:** a warranted item that becomes the standing deal through, e.g., a pocket declaration never auto-fires — FR-5's "auto-heuristic fires at the deal of a warranted item" holds only for launch- and answer-borne deals. Intermittent by construction (depends on which control produced the deal).
- **Fix shape:** funnel those commits through `_commitView` (ack state is inert there) or replicate the heuristic call; add the missing pin.

### F3 — Unbounded rescue step text (fix now, small)

- **Sources:** bmad-review adversarial + edge-case lenses, verified: `packages/core/lib/slicer/rescue_steps.dart:88-107` enforces non-empty text but no upper bound; provider text is stored verbatim as `originContext` and rendered as the card name.
- **Consequence:** a verbose provider answer turns the one-card surface into a wall of text and rides the log/export forever. Fix: a named upper bound rejecting as malformed, exactly as the near-miss folds today.

### F4 — CI never compiles the Android/Kotlin half (process, fix now)

### F5 — Image-path seam defects (defer: Epic 5 pre-work; Epic 4 sends no images)

Three verified at the 4-2↔4-4 seam, all dormant until scan payloads ship (Epic 5):

- **Mime mislabeling:** `lib/egress/image_cap.dart:58-61` passes through any decodable sub-cap bytes untouched, while `lib/egress/byok_wire.dart:264-277` sniffs only JPEG/PNG magic and labels everything else `image/jpeg` — its own doc comment ("every scan payload that reaches the wire carries one of the two") is false for small WebP/GIF/BMP inputs. Guaranteed 4xx misdiagnosed as provider unreachability.
- **Pre-transport decode failure misclassified:** undecodable bytes throw `FormatException` (image_cap.dart:55, :105) which `_causeOf` folds to `malformedResponse` (byok_slicer.dart:161-163) — the taxonomy's delivered-but-unusable bucket — though nothing was ever sent; the classification doc's own honesty claim (byok_slicer.dart:136-139) is broken for this path.
- **Memory ceiling:** `egressPixelCeiling` = 16 MP admits ~64 MB 32-bit rasters plus resize/encode buffers on low-RAM devices — OOM-kill risk mid-camera-flow on hardware the validation emulator does not exhibit.

### F6 — Hardening backlog (defer)

- Keystore cipher work runs synchronously on the platform main looper; first-use key generation can take hundreds of ms (`CredentialsChannel.kt:43-88`). Move to a background executor.
- `on Object` catches fold `Error` subclasses (TypeError etc.) into `providerUnreachable`, hiding programming bugs from the crash guard (`lib/egress/byok_slicer.dart:52-65`, `lib/dispenser/dispenser_controller.dart:609` — the controller's own doc claims a narrower fold than it performs). Narrow to `on Exception`.
- The vault accepts empty plaintext (seals 0 bytes, reports available, sends an empty bearer) — guarded only by the settings UI's trim (`lib/vault/credential_vault.dart:114-137, 176-186, 228-239`). Defense-in-depth for when a second caller exists.
- The rescue read path performs several independent full-log walks per read (rescue decline days, dissolved chains, strip, warm return — `packages/core/lib/derive/rescue.dart:139-162` + weave folds). Unmeasured; single-user log growth makes this a watch item, not a demonstrated problem.
